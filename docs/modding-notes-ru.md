## Манифест и загрузка

Мод — папка или ZIP в <игра>/mods/ либо user://mods/; пользовательский путь по руководству: %APPDATA%/Godot/app_userdata/Terraform Prototype/mods/. Точные пути показывает F8 folders. ZIP содержит mod.json в корне либо в единственной верхней папке. Имена папок с _ и . пропускаются.

По JSON-схеме обязательны id, name, version. id соответствует ^[a-z0-9][a-z0-9_.-]{1,63}$ и остаётся неизменным после публикации. Версия — 1–4 числовых компонента. API в комплектной документации — 1. name/description: строка либо словарь языка; fallback английский. Указывать entry только для кода (обычно main.gd, extends PaxMod). Остальное: authors, tags, game_version, depends, load_after, load_before; схема также допускает homepage/license. Превью thumbnail.png 256×256.

Зависимости/мягкий порядок → порядок пользователя → алфавит id. Поздний мод перекрывает ранний. depends поддерживает id и id>=версия. Выбор сохраняется в user://mods.json. Руководство описывает немедленное включение/отключение в лаунчере и перечитывание перед запуском мира.

## Патчи и локализация

Использовать data/X.patch.json для data/X.json; целые файлы игры не копировать. JSON Merge Patch: рекурсивное слияние, null удаляет ключ. Массивы не сливаются по индексам. Порядок операций: $remove → $edit → $insert_after → $prepend → $append. $replace полностью заменяет объект/массив. $edit содержит $match, изменяет все совпадения; $insert_after вставляет после первого. Частичное сопоставление; список значений означает любое из них. Нет совпадений — предупреждение. Отсутствующий массив считается пустым. Числа 3 и 3.0 сопоставляются одинаково.

data/X.append.txt и .append.md дописывают текст. data/lang/<код>.json сливается с переводами игры. Словарь плоский, значения — строки; одинаковые ключи RU/EN, собственный префикс id мода. Имена тел переводятся через тело_<id тела>. tr_key и %s/%d для подстановок. Идентификаторы и русские ключи данных не переводить. reload сбрасывает кэш, но уже построенные тела требуют новой игры/перезапуска; json res://data/X.json показывает итог.

## Небесные тела

bodies.patch.json: тела, системы, пояса. имя — постоянный id; род: камень/газ/звезда. r и a в километрах; 1 единица сцены = 1000 км. угол в градусах, период в днях. спутник указывает родителя, который обязан идти раньше. Лунам новых планет задавать период явно. система наследуется от родителя. Солнечная система всегда индекс 0, координаты [0,0,0]. Другие системы: имя, звезда, положение_св_лет [x,y,z], масса в солнечных, описание. Масса задаёт кеплеровское движение вокруг центра. Старение Солнца относится только к Солнечной системе.

параметры 0..1: temperature, water, biomass, radiation, atmosphere, urban, magnetic. Земная temperature около 0.35; urban > 0.01 допускает колонию. дом — только одно тело. открыт задаёт первоначальную видимость. кольца — внутренний/внешний радиусы в км; газ: полос и цвета; камень: цвет_породы.

карта — префикс без суффикса, например res://mods/<id>/planets/xeno. Карты 2:1: _albedo (png/jpg/webp), _height.png (белое выше), _ocean.png (белое вода). карта_море 0..1. Без карт возможна процедурная поверхность. шейдер — spatial .gdshader; шейдер_параметры — числа, векторы или пути текстур. меш — GLB/glTF, единица модели равна радиусу тела.

Для новых каменных тел автоматически создаются 24 провинции; поля провинций и провинции_имена меняют генерацию. Кэш user://mod_cache/regions/. Собственные границы: data/regions/тело_<имя>.json + .bin; подробный формат отсылает к исходнику tools/провинции/без_карт.py, которого в прочитанном комплекте документации нет.

## Код и состояние

PaxMod живёт весь процесс, переживает смену миров. Pax.game null вне мира. _mod_loaded — команды/настройки; _mod_unloaded — уборка; _body_created — материалы и узлы; _world_ready — UI; _days_passed(game, from_day, days) — симуляция; _ship_arrived — прибытие; _data_reloaded — обновление своих данных. При загрузке _game_loaded выполняется перед _world_ready. Состояние мира сохранять через _save_state → _game_loaded, только JSON-типы. Настройки между сейвами: get_setting/set_setting, user://mod_settings/<id>.json. При реализации учитывать смену миров, повторное создание UI и сброс состояния новой партии.

Не выводить тип через := из Variant: явно указывать тип или преобразование. Для ресурсов мода применять path, load_json, texture, sound, model, shader, scene. Шаблон запрещает load() для png/jpg/ogg/glb: эти ресурсы загружаются помощниками без импорта Godot.

PaxGame: day/date/date_text/set_speed; body_names/body/body_node/body_material/body_params/set_body_param; home_body/focused_body/focus/set_discovered; systems/body_system/system_bodies/distance_km/distance_ly/travel_days; resources/add_resource/colonies/people; add_character/has_character; factions/player_faction; toast/chronicle/tr_key/language; add_bottom_button/add_window/hud_layer/scene_root/camera; launch_ship/ships.

body/resources/factions/ships возвращают живые записи (изменять осторожно); Pax.json возвращает глубокую копию итоговых данных. body может вернуть {}, body_node/material — null; distance_km возвращает -1 при неизвестном теле. game.main/sim/world/stock — нестабильные внутренности, сначала выбирать стабильный API.

UI строить в _world_ready. add_window возвращает PanelContainer; add_bottom_button — Button. Для 3D действует плавающее начало координат: связанные объекты прикреплять к body_node, масштаб относительно радиуса тела.

Pax: сигналы mods_loaded, world_ready, days_passed, body_created, saving, loaded, ship_launched, ship_arrived, data_reloaded, log_added. Методы работы с данными: json/text/exists/resolve/list_files и загрузчики ресурсов; моды: mods/has_mod/get_mod/reload_mods; консоль: register_command/run_command; переводы и лог: tr_key/log_line.
